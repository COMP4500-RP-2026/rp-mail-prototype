# RP Mail：Windows 使用说明

macOS 请看 [macOS 使用说明](macOS使用说明.md)。

界面默认使用英文。右上角的 **English / 中文** 下拉框可以切换界面语言，软件会记住选择。切换时保留工作清单、选中记录、编辑内容和当前标签页；查找或发送进行中请等操作结束后再切换。邮件正文始终保持英文。英文按钮 Find emails 对应“自动查找邮箱”，Account settings 对应“个人邮箱设置”，Send selected 对应“发送选中项”。

## 打开软件

解压整个压缩包，在 RPMail 文件夹双击 **RPMail.exe**。不需要安装 Python。请保留旁边的 `_internal` 文件夹，不要只复制 exe。软件需要 Windows 64 位，并且保存位置必须可写。

主界面采用邮件客户端布局：左侧分类、中间清单、右侧编辑与邮件预览。软件以个人身份撰写英文邮件，用“I”和你的姓名，不使用学校或团队身份。

## 第一次使用

1. 点击“个人邮箱设置”，填写你的英文署名和个人邮箱。回复邮箱可留空。
2. 使用 Classic Outlook 方式时，在 **Windows 经典版 Outlook** 中添加并登录同一个个人邮箱；点击软件的“检查发件连接”。也可在设置中选择 SMTP，按邮件服务提供方或学校管理员给出的参数配置。
3. 当前 GitHub 仓库不附带真实研究数据。导入自己的 CSV 或 xlsx；xlsx 读取保存时的活动工作表，第一行必须是字段名；不支持旧式 xls。
4. 选择记录，点击“自动查找邮箱”。软件依次尝试 Microsoft Edge、Google Chrome 和 Playwright Chromium，从 project_url 对应的 RP+ 项目网站读取成员，再到成员公开主页读取邮箱。优先选择同时出现在成果作者栏中的同一人员主页，再考虑项目负责人和其他成员。自动填写空白的姓名、邮箱和项目名称；原有手工填写的联系人不会被覆盖。在“邮箱来源与候选”可查看来源、切换联系人。核对推荐理由及其他内容后勾选确认框，点击“保存修改并更新预览”。发表日期、资助机构和项目时间缺失时会在邮件中注明暂缺。
5. 点击“邮件预览”查看完整邮件，再点“试发给自己”。此操作只把选中记录中的第一条合格邮件发送给你的个人发件邮箱。
6. 收到测试邮件并确认内容后，选择记录并点“发送选中项”；可以按 Ctrl / Shift 多选。软件列明发件人、数量和收件人摘要供最终确认。

也可点击“生成草稿”，到 Outlook 草稿箱逐封查看和手动发送。草稿记录会被锁定，后续自动发送会跳过它们，避免你手动发送后又被重复发送。

## 数据与发送记录

- 修改自动保存在 `personal_data/mailing_list.csv`，不改原文件。可用“导出清单”保存为 CSV UTF-8。
- 原始 CSV 有部分乱码；软件没有猜测修复，请核对标题。
- 原数据没有姓名、邮箱等信息。软件现在支持从项目成员公开主页自动读取邮箱，但不会猜测地址。项目成员没有主页链接、主页没有公开邮箱时，会显示相应状态，需人工补充。
- 同一论文 UUID + 项目 UUID + 收件邮箱只处理一次；已存在关系的条目自动跳过。收件人有多个关系时会收到多封邮件。
- `send_history.sqlite3` 是防重复发送记录。请与软件一起保留；不要删除或另解压一份软件来重发。若你使用过之前的脚本并已发送邮件，请在首次使用桌面版前，将原来的 `send_history.sqlite3` 复制到 RPMail.exe 同目录，保持历史连续。
- “已交给 Outlook”不代表已投递，可能仍在发件箱。请在 Outlook 中查看已发送、退信和回复。
- “结果待核查”不会自动重试，请先检查 Outlook 中实际状态。操作结束前请保持软件和 Outlook 打开。
- 软件不读取邮箱、不自动处理回复、不修改 RP+。研究人员可回复 Confirmed / Not related / Unsure / Correction / Not my research output。

## 兼容性

自动查找需要 Edge、Chrome 或 Playwright Chromium，以及互联网连接；不需要在浏览器登录邮箱。首次点击会打开一个独立浏览器窗口供查看进度，结束后关闭。查找默认处理选中记录；没有选中时处理尚未填写邮箱的记录。重复网页在本批缓存，逐页限速读取；“停止查找”会在当前网页读取结束后停止并保留已完成的结果。

只读取项目成员列表及其公开邮箱，不抓取网页页脚或其他成果中的无关邮箱。邮箱来源、匹配依据、抓取时间和全部候选保存在清单中。多个候选时默认取优先级最高者（同级按网页顺序），并不代表此人已确认研究关系；不会自动勾选“已核对”。仅发现同一个人员主页同时在项目页和成果作者栏时，才自动填写对应的英文推荐理由；不会臆造资助致谢证据。

单个页面超时会重试一次；单个项目页或成员主页读取失败后会保留结果并继续处理。论文页无法读取时仍可查找项目成员邮箱，但不会宣称该成员也是论文作者。网站拒绝访问（401/403）、限流（429）、验证页面或浏览器关闭时会停止本批并说明原因，不会绕过验证码。项目页有成员姓名但没有链接时，此版本不通过猜测姓名搜索其他人的邮箱。网页版式变化也可能需要更新解析规则。

若提示“邮箱查找中断”，请查看提示里的具体原因；完整错误、正在访问的网页地址记录在 `personal_data/email_lookup.log`。重试前保留这份日志，下一次查找会覆盖它。无需提供个人邮箱密码。

选择 Classic Outlook 方式时，个人邮箱需能作为一个实际发件账户加入经典版 Outlook。**新版 Outlook 不支持此连接方式**，即使它也安装在电脑上。SMTP 是独立的发信方式，需要邮件服务允许相应的认证方式。参见[微软功能比较](https://support.microsoft.com/en-us/outlook/getstarted/feature-comparison-between-new-outlook-and-classic-outlook)。

它不是完整邮箱客户端：不提供收件箱同步、账号注册或内置邮箱密码登录。Outlook 如显示程序访问提示，请按账户和电脑的安全设置处理；软件不会关闭这些设置。

原 Windows 原型曾报告 5,441 条记录导入、草稿与发送去重逻辑及公开邮箱提取测试。此仓库的自动化测试使用模拟发送；没有验证当前电脑上的真实 Outlook 或 SMTP 投递，也没有发送真实邮件。

升级时不要覆盖或删除已有的 personal_data 和 send_history.sqlite3；将新程序与 _internal 更新到原目录，保留这两项用户数据。
